# 关卡难度量化模型设计（Stage Difficulty Model）

日期：2026-08-09
状态：已确认方向（线性递增、以单人模式校准）

## 背景与目标

当前 1-20 关的难度由两套互不相干的参数决定：

- 地图侧：`scripts/check-stage-difficulty.mjs` 只校验地形复杂度、基地保护、最短路径等硬指标；
- 敌人侧：`src/main.ts` 的 `STAGE_TUNING`（刷怪间隔、同屏上限、四种坦克配比）纯手调。

没有任何指标把两者加总，导致"有的关按理更难实际更简单"无法被检测。本设计定义一个可计算、可回归测试的综合难度指数，并要求 20 关沿一条直线递增。

## 难度指数公式

### 敌人得分 EnemyScore

```
坦克威胁值  threat(kind) = hp × (1 + 0.25·[速度 > 34] + 0.25·[弹速 > 120])

  basic = 1.00   （1 HP，慢速，慢弹）
  fast  = 1.25   （1 HP，快速）
  power = 1.25   （1 HP，快弹）
  armor = 4.00   （4 HP）

关卡总威胁  StageThreat = Σ enemyMix[kind] × threat(kind)
刷怪压力    Pressure    = maxEnemiesOnField ÷ enemySpawnInterval
敌人得分    EnemyScore  = StageThreat × Pressure
```

权重依据：HP 是全歼所需的射击次数，是主导成本；速度与弹速各加 25% 的压迫修正。阈值为**严格大于**（basic 的速度/弹速恰好等于基准值 34/120，不享受加成）。

### 地图得分 MapScore

```
MapScore = 地形复杂度（S + 2W + F + I）
         + 基地开口环 × 4
         + max(0, 18 − 出生点到基地最短路径)
         + 直通车道数 × 5
```

- **地形复杂度 / 基地开口环 / 最短路径**：沿用 `check-stage-difficulty.mjs` 现有定义与数值（最短路径 = 现有 Dijkstra 度量，砖块代价 5，终点为基地前沿格，对三个固定出生点取最小）；
- **直通车道**：出生点列 x ∈ {0, 6, 12} 中，整列 13 格全部为可通行地块（可通行集 = `{'.', 'F', 'I'}`，即 B/S/W 均阻断）的列。实测全部 20 张地图中只有第 1、3 关各存在 2 条（左右边缘 x=0、x=12），该项精准刻画了"敌人可以直接攻击基地"的体感。

### 综合难度

```
D(stage) = EnemyScore + MapScore
```

所有 D 值以**未取整的浮点数**参与比较（单调、容差带、跳变上限均如此），表格中的整数仅为展示用四舍五入。

## 校验规则（写入 check-stage-difficulty.mjs，CI 强制）

新增以下 4 条规则；**现有全部校验原样保留**（包括旧版地图分数 `difficultyScore` 的单调检查——旧公式不含直通车道项，仍单调，不受影响）。

1. **单调不减**：`D(s) ≥ D(s−1)`；
2. **线性贴合**：目标直线 `D*(s) = 27 + (s−1) × 16.2`（由当前 D(1)=27、D(20)=335 锚定），容差带 ±16；
3. **跳变上限**：`D(s) − D(s−1) ≤ 30`，禁止断崖式难度突增；
4. **教学关例外**：第 1-3 关不设目标带下界（新手引导期允许低于直线），但单调、跳变上限与目标带**上界**仍然适用。

### 调整（只动 2 关的 `STAGE_TUNING`）

现有不变式要求刷怪间隔跨关**单调不增**（`checkStageTuning()`），因此两关联动调整：

- **Stage 12**：`enemySpawnInterval` 1.35 → 1.25
  - D：186 → 197（EnemyScore 138 → 149），进入容差带 [189, 221]；
- **Stage 13**：`enemySpawnInterval` 1.3 → 1.25，且 `enemyMix` `{1,5,6,8}` → `{1,5,8,6}`（armor 8→6，power 6→8）
  - 间隔若不动，会因 Stage 12 降到 1.25 而违反单调不增不变式，故同步降至 1.25（与 Stage 14 的 1.25 持平，不违规）；
  - D：229 → 214（StageThreat 46.75 → 41.25，Pressure 3.85 → 4.0），进入容差带 [205, 237]；
  - 调整后跳变：12→13 ≈ +17，13→14 ≈ +23，均 ≤ 30。

其余 18 关的参数与地图一律不动。

## 单人 / 双人策略

以**单人模式（1P）校准全部曲线**。双人模式遵循原作 Battle City 设定：敌人参数不随人数变化，双人天然更简单，定位为"合作减负 / 带新人"玩法，不做动态补偿。经验换算：双人有效难度约等于单人曲线前移 3-4 关（双倍火力与命池），此换算仅写入文档供参考，不进入校验。

## 非目标（Out of Scope）

- 不重设计任何地图（第 3 关侧翼开放问题已由 armor 移除 + 直通车道分解释，暂不改动地图）；
- 不做双人模式难度补偿；
- 不引入玩家战力成长曲线（道具拾取属于随机因素，QA 的 powerUpFrames 仅观察）。

## 附录 A：教学关软化（2026-08-09，玩家反馈后追加）

反馈：第 2、3 关敌人从两翼同时压下且快速坦克多，单人守不住。

调整：

- **Stage 1 地图**：在第 9 行两侧各加一块砖（`(0,9)`、`(12,9)`），封闭两条直通车道。教学关不应有侧翼高速通道，且为后续软化腾出单调性空间。D：27.3 → 17.3；
- **Stage 2**：`maxEnemiesOnField` 3→2，`enemyMix` fast 4→2（basic 补至 16）。D：29.8 → 21.2；
- **Stage 3**：`maxEnemiesOnField` 3→2，`enemyMix` fast 4→2（basic 补至 16）。D：43.0 → 33.3。

规则修订：

- **跳变上限的适用范围改为 4→5 及以后**（即 `stage > ONBOARDING_STAGES + 1`）。3→4 是教学期"毕业跳"——armor、钢板、同屏上限同时登场是有意设计，允许超过 30（当前约 +39）。该跳变是全曲线唯一例外，QA 中 Stage 4 的 playerDeaths=18 为全前期最高，后续如收到反馈再单独评估。

QA 验证：Stage 2 baseHitRuns 9→7、playerDeaths 2→0；Stage 3 playerDeaths 0→1，均无异常。
